# НарядAI

**«Наряд выдан — ИИ на контроле»**

Мобильная веб-система для выдачи, выполнения и контроля производственных нарядов. Проект реализован на **Blazor Web App / .NET 10** с интерактивным серверным рендерингом, **PostgreSQL** в качестве базы данных и **SignalR** для синхронизации состояний в реальном времени.

Приложение рассчитано на работу с компьютера и телефона. PWA-манифест позволяет установить систему на Android как приложение.

> Проект содержит демонстрационные данные для хакатона. Они предназначены для локальной разработки и показа функциональности и не являются производственными данными.

## 1. Стек проекта

- **.NET 10 / ASP.NET Core**
- **Blazor Web App** с интерактивным серверным рендерингом
- **MudBlazor** — UI-компоненты
- **Entity Framework Core** — работа с БД и миграции
- **PostgreSQL 15+** — основная база данных
- **SignalR** — обновление статусов нарядов в реальном времени
- **PWA / Service Worker** — установка на Android и базовый offline-shell
- **Excel export** — выгрузка отчётов
- **ИИ-модуль** — локальные правила и опциональный внешний LLM-провайдер

## 3. Структура конфигурации

Основная конфигурация находится в `appsettings.json` и, при необходимости, в `appsettings.Development.json`.

Минимально приложению нужна строка подключения PostgreSQL:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=5432;Database=naryadai;Username=postgres;Password=<ваш пароль>"
  }
}
```

Для ИИ может использоваться внешний провайдер. Ключи конфигурации приложения:

```text
Ai__AnthropicEndpoint
Ai__ApiKey
Ai__Model
```

В JSON это соответствует секции:

```json
{
  "Ai": {
    "AnthropicEndpoint": "<endpoint>",
    "ApiKey": "<api-key>",
    "Model": "<model>"
  }
}
```

Если внешний ИИ-провайдер не настроен, система использует локальную логику/правила там, где она предусмотрена приложением.

### Переменные окружения

Рекомендуемый вариант для локального запуска — не записывать пароль PostgreSQL и API-ключ в Git, а задавать их в текущем окне PowerShell:

```powershell
$env:ConnectionStrings__DefaultConnection = "Host=localhost;Port=5432;Database=naryadai;Username=postgres;Password=<ваш пароль>"
$env:Ai__AnthropicEndpoint = "<endpoint>"
$env:Ai__ApiKey = "<api-key>"
$env:Ai__Model = "<model>"
```

Переменная конфигурации с двумя подчёркиваниями `__` соответствует вложенному разделу JSON. Например:

```text
ConnectionStrings__DefaultConnection
```

соответствует:

```json
"ConnectionStrings": {
  "DefaultConnection": "..."
}
```

## 4. Подключение PostgreSQL

### Вариант A — создать пустую базу вручную

В PostgreSQL создайте базу с названием, например, `naryadai`.

Через pgAdmin:

1. Подключитесь к серверу PostgreSQL.
2. Откройте **Databases**.
3. Создайте новую БД `naryadai`.
4. Владелец — пользователь `postgres` или другой пользователь, указанный в строке подключения.

Через `psql`:

```powershell
createdb -h localhost -U postgres naryadai
```

После создания укажите подключение:

```powershell
$env:ConnectionStrings__DefaultConnection = "Host=localhost;Port=5432;Database=naryadai;Username=postgres;Password=<ваш пароль>"
```

## 5. Первый запуск

Перейдите в корень репозитория и выполните:

```powershell
dotnet restore .\NaryadAi\NaryadAi.csproj
```

Затем:

```powershell
dotnet run --project .\NaryadAi\NaryadAi.csproj --launch-profile http
```

При запуске приложение применяет существующие EF Core миграции автоматически.

По умолчанию локальный HTTP-профиль доступен по адресу:

```text
http://localhost:5237
```

Точный адрес всегда указан в консоли строкой вида:

```text
Now listening on: http://localhost:5237
```

Откройте этот адрес в браузере.

## 6. Что происходит при первом запуске пустой БД

Если база действительно пустая, приложение создаёт структуру PostgreSQL через EF Core и добавляет стартовую локальную учётную запись администратора.

Локальные стартовые данные:

```text
Логин: admin
Пароль: admin
```

Эти данные предназначены только для локальной разработки.

После этого администратор может работать со справочниками и сотрудниками через:

```text
/admin/employees
/admin/dictionaries
```

## 7. Демонстрационные данные для хакатона

Для защиты проекта предусмотрен отдельный детерминированный набор демонстрационных данных.

Он создаётся **только в Development** и **только при явном включении параметра**:

```powershell
$env:Seed__EnableDemoData = "true"
```

После этого запускается приложение:

```powershell
dotnet run --project .\NaryadAi\NaryadAi.csproj --launch-profile http
```

Набор содержит:

- 4 производственных участка;
- 25 единиц оборудования;
- 2 мастера;
- 15 исполнителей в 3 бригадах;
- 20 шифров неисправностей;
- 40 материалов;
- 500+ исторических нарядов за 3 месяца;
- дополнительные демонстрационные наряды для сценария защиты;
- заранее заложенные повторные неисправности и аномалии для аналитики.

### Важно

Демо-сеeder предназначен для **пустой базы**. Если в БД уже есть производственные справочники или наряды, заполнение демонстрационными данными отменяется без изменения существующих данных.

Поэтому не следует включать demo-seed на базе с реальными рабочими данными.

## 9. Как полностью сбросить базу и начать заново

**Внимание: все данные выбранной PostgreSQL-базы будут удалены.**

Перед сбросом остановите приложение.

### Вариант A — через EF Core

Из корня проекта:

```powershell
dotnet ef database drop --project .\NaryadAi\NaryadAi.csproj --force
```

После этого снова примените миграции:

```powershell
dotnet ef database update --project .\NaryadAi\NaryadAi.csproj
```

Если команда `dotnet ef` отсутствует:

```powershell
dotnet tool install --global dotnet-ef
```

или обновите уже установленный инструмент:

```powershell
dotnet tool update --global dotnet-ef
```

### Вариант B — через pgAdmin

1. Остановите приложение.
2. Подключитесь к серверу PostgreSQL.
3. Удалите БД `naryadai`.
4. Создайте её заново.
5. Запустите приложение.
6. EF Core снова применит миграции.
7. При необходимости включите demo-seed.

### Вариант C — через SQL

Подключитесь не к удаляемой БД, а к служебной БД, например `postgres`, затем выполните:

```sql
SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE datname = 'naryadai'
  AND pid <> pg_backend_pid();

DROP DATABASE naryadai;
CREATE DATABASE naryadai;
```

После этого:

```powershell
dotnet run --project .\NaryadAi\NaryadAi.csproj --launch-profile http
```

И при необходимости включите:

```powershell
$env:Seed__EnableDemoData = "true"
```

## 10. Как восстановить готовый SQL-дамп

Если вместо сидера используется готовая PostgreSQL-база в виде SQL-файла, сначала создайте пустую БД, затем импортируйте дамп.

Для обычного `.sql`:

```powershell
psql -h localhost -U postgres -d naryadai -f .\backup.sql
```

Для PostgreSQL custom-format (`.backup` / `.dump`):

```powershell
pg_restore -h localhost -U postgres -d naryadai .\backup.backup
```

После восстановления проверьте, что строка подключения приложения указывает именно на эту БД:

```text
Database=naryadai
```

В этом режиме demo-seed обычно не требуется: данные уже находятся в БД.

## 11. Важное различие: миграции, сидер и SQL-данные

В проекте есть три разные вещи:

### EF Core migrations

Создают и изменяют структуру БД: таблицы, связи, индексы и другие элементы схемы.

Они применяются при запуске приложения автоматически.

### Стартовая локальная инициализация

На пустой БД создаётся стартовый администратор `admin / admin`.

### Demo Data Seeder

Добавляет большой набор тестовых данных для демонстрации аналитики, работы мастера, исполнителя и руководителя.

Это **данные**, а не структура БД.

Поэтому обычный рабочий сценарий выглядит так:

```text
Пустая PostgreSQL БД
        ↓
EF Core migrations
        ↓
Структура таблиц
        ↓
Стартовый Admin
        ↓
Demo Seeder (только при включении)
        ↓
Готовая демо-БД
```

## 13. ИИ-модули

ИИ в системе используется как цифровой контролёр смены.

В зависимости от доступных модулей система выполняет:

- контроль сроков нарядов;
- предупреждения и фиксацию просрочек;
- проверку заполненности закрытия;
- проверку соответствия работ описанной проблеме;
- проверку логичности списанных материалов;
- анализ фотографий;
- формирование оценки и пояснения;
- поиск аномалий в исторических данных;
- подготовку аналитических выводов для руководителя.

Если внешний ИИ-провайдер не настроен, используются встроенные локальные правила там, где они предусмотрены приложением.

## 14. Контроль сроков

Система содержит фоновый мониторинг сроков нарядов.

Мониторинг работает в фоне и регулярно проверяет активные наряды.

Для демонстрации просрочки можно создать второй наряд с коротким дедлайном, например **на 3 минуты вперёд**. После истечения времени фоновый мониторинг фиксирует событие просрочки.

В приложении дедлайны хранятся в UTC, а в интерфейсе работают с локальным временем пользователя. Поэтому мастеру не нужно вручную пересчитывать время в UTC: при создании наряда можно указывать обычное местное время.

## 15. Запуск на телефоне

### Локальная разработка

`localhost` работает на компьютере, но сам по себе не даёт телефону доступ к серверу.

Для проверки на телефоне в локальной сети компьютер и телефон должны находиться в одной сети, а сервер должен быть доступен по адресу компьютера.

### PWA в опубликованной среде

Для установки приложения на Android нужен опубликованный **HTTPS**-адрес.

В Chrome:

```text
Открыть сайт → меню браузера → Установить приложение / Добавить на главный экран
```

Обычный HTTP по локальному IP не подходит для полноценного сценария установки PWA.

## 16. Offline-режим

Service Worker кэширует статические ресурсы и позволяет показать страницу недоступности при потере соединения.

При этом рабочие данные нарядов хранятся на сервере, а полноценная автономная синхронизация нарядов в текущей версии не реализована.

## 18. Типовые ошибки

### `password authentication failed for user "postgres"`

Неверный пароль PostgreSQL или пользователь в строке подключения.

Проверьте:

```text
Host
Port
Database
Username
Password
```

### `database "naryadai" does not exist`

База ещё не создана. Создайте её через pgAdmin или `createdb`.

### Таблицы не существуют

Запустите приложение ещё раз: EF Core должен применить миграции автоматически.

Также можно явно выполнить:

```powershell
dotnet ef database update --project .\NaryadAi\NaryadAi.csproj
```

### Demo-данные не появились

Проверьте сразу три условия:

1. Приложение запущено в `Development`.
2. В текущем PowerShell включён параметр:

```powershell
$env:Seed__EnableDemoData = "true"
```

3. База не содержит уже существующих рабочих справочников/нарядов, при которых seeder отменяет заполнение.

### Изменил код, но приложение показывает старое состояние

Остановите приложение и снова выполните:

```powershell
dotnet build .\NaryadAi\NaryadAi.csproj
```

Затем запустите его заново.

После первоначального заполнения демо-базы не нужно удалять её перед каждой репетицией. Можно использовать одну подготовленную базу для демонстрации, а перед новым чистым прогоном выполнить полный сброс по инструкции выше.

## 20. Безопасность

Для локального хакатонного запуска допускается тестовая конфигурация и демонстрационная база.

При публикации проекта или переносе в реальную среду:

- не храните рабочий пароль PostgreSQL в Git;
- не храните рабочий API-ключ ИИ в репозитории;
- замените тестовые учётные данные;
- используйте отдельную БД для демонстрации и отдельную БД для production;
- не загружайте реальные персональные данные сотрудников во внешний ИИ без необходимого обезличивания и разрешения;
- проверьте права доступа к PostgreSQL и к опубликованному приложению.
