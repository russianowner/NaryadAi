## Цель и требования

Рабочий MVP системы выдачи и контроля промышленных нарядов для кейса «Костанайские минералы». Пользователь подтвердил стек C# и PWA. Исходные материалы: PDF `C:\Users\souja\Downloads\Кейс №1 Костанайские минералы рус (1).pdf` и скрин технических требований. Ключевые требования: Android обязательно, iOS желательно; PWA допустима; уведомления; обновления статусов не дольше 5 секунд; интерфейс на русском (казахский — плюс); большие кнопки для перчаток; каждая роль видит свои функции; фото сжимаются, загрузка до 10 секунд при мобильной сети; исходный код с инструкцией запуска.

Пользователь хочет продолжать работу в существующем репозитории и просил сначала проанализировать его, затем выполнить кейс целиком. Друг параллельно пишет авторизацию: изменения авторизации/его незакоммиченные файлы не заменять без проверки и согласования интерфейсов.

### Интерфейс и сценарии

- `/login` — вход; `/master` — мастерская панель/канбан и создание наряда; `/worker` — панель исполнителя и закрытие наряда; `/profile` — профиль; `/reports` — отчёты и экспорт Excel; `/admin/employees`, `/admin/dictionaries` — администрирование.
- Большие кнопки и мобильная/PWA компоновка реализуются в Razor/CSS страницах; Worker-панель поддерживает форму завершения, выбор шифра неисправности, списание материалов, комментарий и загрузку фото «после».
- После недавней доработки форма исполнителя загружает список материалов, выбирает справочную единицу измерения.
- Мастер видит исполнителей со статусами и рабочую канбан-доску.
- Реалтайм: SignalR `WorkOrdersHub`, scoped `WorkOrderChangeNotifier`; README указывает обновления через SignalR.
- `wwwroot/manifest.json`, `service-worker.js`, offline-страница, иконки PWA присутствуют.

### ИИ, фото и сроки

- `AiReviewService.cs`: вызов Anthropic/Claude при конфигурации ключа и локальный fallback/rule review. Результат сохраняется в `AiEvaluation`; мастеру доступно подтверждение/возврат.
- `WorkOrderPhotoService.cs`: обработка фото и ограничение размера; в текущей реализации есть проверка повторов по хешу байтов, но она не заменяет проверку сходства изображения и EXIF/сжатия.
- `WorkOrderDeadlineMonitor.cs`: фоновое сканирование дедлайнов/эскалаций, уведомления в приложении и события. В тестовой БД фоновая задача записала SLA-события; ранее в логе наблюдались ошибки запросов/конкуренции — нужно проверить их на свежем запуске.
- `EmployeeRatingService.cs`: подсчёт рейтинга на базе оценок и процесса. Полная логика кейса и аналитическая калибровка не подтверждены.
- Push через Firebase/FCM пока не считать реализованным: сейчас есть внутренняя/SignalR доставка. Проверить перед заявлением о готовности.

## Запуск локально

Из PowerShell в корне репозитория; нужен .NET 10 SDK и доступный PostgreSQL. Указать собственную локальную connection string, не коммитить её:

```powershell
$env:ConnectionStrings__DefaultConnection = "Host=localhost;Port=5432;Database=naryadai;Username=postgres;Password=<локальный пароль>"
dotnet restore .\NaryadAi\NaryadAi.csproj
dotnet run --project .\NaryadAi\NaryadAi.csproj --launch-profile http
```

Для отдельной пустой демо-БД (создать её заранее и использовать исключительно для демо):

```powershell
$env:ConnectionStrings__DefaultConnection = "Host=localhost;Port=5432;Database=naryadai_demo;Username=postgres;Password=<локальный пароль>"
$env:Seed__EnableDemoData = "true"
dotnet run --project .\NaryadAi\NaryadAi.csproj --launch-profile http
```

См. также корневой `README.md`. По умолчанию EF применяет миграции на старте. Демозапуск может занять время, потому что заполняется 500 нарядов. Чтобы проверить PWA на физическом Android, нужен доступный с телефона HTTPS-origin; localhost телефона — это сам телефон, а не Windows-хост. Фото/камера, service worker и push требуют теста через HTTPS (localhost — исключение только на том же устройстве).

## Что осталось для завершения кейса

1. **Auth/роли:** интегрировать работу друга; серверная проверка входа и прав на страницы, действия, SignalR; хеширование PIN/пароля и безопасное истечение сессии. Проверить межролевой доступ.
2. **Сценарии:** ручной E2E через мастер → исполнитель → фото/материалы/завершение → ИИ → мастер принимает/возвращает. Проверить все допустимые и запрещённые переходы, фиксацию времён и event log. Проверить форму мастера на минимальное число нажатий и все обязательные поля.
3. **SLA:** исправить/разобрать ошибки `WorkOrderDeadlineMonitor`; проверить 30-мин напоминание, overdue, непринятие 10 мин/3 мин (аварийный), однократность, правильную классификацию аварийных работ, эскалацию мастеру и предложение замены.
4. **ИИ:** проверить тексты и fallback; добавить/проверить разумность списания материалов относительно кода неисправности; сохранить понятный вердикт, объяснение и финальную оценку мастера. Сейчас не заявлять, что ИИ автоматически валидирует фото.
5. **Фото:** соответствовать кейсу — сжатие/размер, мобильная загрузка <=10 секунд, защита от повторных фото не только по идентичному хешу, метаданные и сопоставление «до/после». Проверить большие фото и плохую сеть.
6. **Push/PWA:** подключить push (Firebase/FCM или согласованный эквивалент), аварийный красный приоритет уведомлений, проверить offline cache/установку Android, убедиться в обновлении <=5 секунд на физическом мобильном клиенте. Сейчас SignalR/in-app не равны push.
7. **RU/KZ и доступность:** аудит казахской локализации по всем страницам; текущая локализация частичная. Проверить контраст/крупные кнопки/перчаточный сценарий на телефоне.
8. **Отчётность/рейтинг:** проверить экспорт и агрегации на демо-данных, реализовать/сверить формулу кейса (сроки, возвраты, отказы, оценка мастера/ИИ, повторяемость/сложность если требуется).
9. **Надёжность/сдача:** свежая сборка, запуск миграций на чистой локальной БД, пользовательский smoke-test; README и тестовые роли; проверить, какие финальные файлы требует кейс (презентация/видео/репозиторий) перед сдачей.

Ориентировочная прежняя оценка готовности — около 60% MVP, это экспертная оценка по объёму кейса, не формальный подсчёт завершённых acceptance criteria. Остаток прежде всего связан с безопасностью, push, SLA/E2E и соответствием на мобильном устройстве.
